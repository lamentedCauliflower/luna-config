# Paper Printing And Scanning Are Driverless And Discovered, Never Declared

The household printer is an HP OfficeJet Pro 7740 series (an MFP: printer, flatbed, ADF, fax) on the LAN. Interrogating it decided the whole shape of the feature. Its IPP attributes advertise `urf-supported`, `image/urf`, `image/pwg-raster` and `application/PCLm` — IPP Everywhere / AirPrint — and its eSCL endpoint reports `pwg:Version 2.5` with both `Platen` and `Adf` sources. Both halves are therefore driverless: CUPS drives it with no PPD and SANE scans it with no vendor backend. `hplip` and HP's unfree plugin are not installed on any host, and nothing in this repo pins a driver package that a nixpkgs bump could break.

Printing and scanning are separate modules (`features/printing.nix`, `features/scanning.nix`), imported by cleoDesktop and yuroLaptop only. lunaServer is headless and, because every client talks to the printer directly, has no reason to act as a print server; keeping it out also avoids contending with the `services.avahi` block `hosts/lunaServer/samba-server.nix` already owns for Samba. mewoSteamdeck could take either module with a one-line import if printing from Desktop Mode ever matters.

Three decisions look like omissions in the resulting code, and are deliberate:

1. **No `hardware.printers.ensurePrinters`.** A declarative queue is the obvious instinct in a repo like this, but `ensurePrinters` runs `lpadmin -m everywhere` during activation, which queries the printer over the network. That would make `nh os switch` on a laptop depend on being at home, and `nh os build` would not catch it — activation is not build. It also pins the printer's DHCP address. Discovery costs a generated queue name that varies, which only matters if something hardcodes `lp -d <queue>`; nothing does. Revisit if a script ever needs a stable queue name, and if so add the queue on cleoDesktop only.

2. **`services.printing.browsed.enable = false`.** Its default is `config.services.avahi.enable`, so enabling avahi silently starts cups-browsed too. cupsd 2.4 already browses DNS-SD and builds temporary queues on demand, so browsed only adds a second daemon and the UDP 631 listener behind the September 2024 CUPS chain (CVE-2024-47176 and friends). cleoDesktop puts `br0` in `networking.firewall.trustedInterfaces`, so a listener there faces the entire LAN with no firewall in between. The version in nixpkgs postdates those fixes; the point is that the daemon buys nothing to justify the exposure. Written out explicitly so a change to the nixpkgs default cannot turn it back on unnoticed.

3. **`nssmdns4` / `nssmdns6` stay `false`.** Both `cups` and `sane-airscan` build against `avahi-0.8` and browse DNS-SD through avahi-daemon's D-Bus API; nss-mdns only affects glibc *hostname* resolution and is not in either path. Enabling it inserts `mdns4_minimal [NOTFOUND=return]` ahead of `dns` in `/etc/nsswitch.conf`, which interacts badly with this network's naming. nss-mdns claims a `.local` name only when it has exactly two labels, so the three-label service names (`jellyfin.luna.local`, `syncthing.${dnsName}.local`, …) return `NSS_STATUS_UNAVAIL` and fall through to pihole unharmed — but the bare `luna.local` record pihole serves via `address=/.luna.local/` in `containers/pihole.nix` has two labels. It would be routed to mDNS, find no responder, return `NOTFOUND`, and stop before ever reaching DNS. The usual escape hatches do not apply: pihole answers NXDOMAIN for `SOA local`, so nss-mdns's local-SOA check does not disqualify the name, and `/etc/mdns.allow` is only consulted by the non-minimal module. The cost of leaving it off is that `.local` hostnames are not resolvable by `ping`/browser on these hosts, which nothing currently relies on.

A fourth, smaller call: `hardware.sane.disabledDefaultBackends = [ "escl" ]`. sane-backends 1.4.0 enables its own `escl` backend in `dll.conf`, and it discovers the same eSCL device as sane-airscan, so both enabled means every scan dialog lists this printer twice with nothing to distinguish the entries. airscan is kept because it handles ADF and duplex better — relevant on a machine whose ADF is half the reason to scan — and additionally speaks WSD. `hardware.sane.openFirewall` stays `false`; it exists for Canon's BJNP, while airscan is client-initiated HTTP plus D-Bus discovery, with nothing listening.

The scan frontend (`simple-scan`) ships in `features/scanning.nix`'s `environment.systemPackages` rather than in a home module, following `features/hyprland.nix`. `homeModules.isaacConfiguration` is shared by all three desktop hosts, so putting it there would install a scan app on mewoSteamdeck, which has no SANE backend.
