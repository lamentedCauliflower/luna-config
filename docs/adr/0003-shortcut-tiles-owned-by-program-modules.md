# Game Mode Tiles Are Declared By The Module That Owns The Program

`hostConfig.steamShortcuts.shortcuts.<name>` is an attrset-of-submodules option (caddy-virtualHosts-style): any NixOS module may declare a Non-Steam Shortcut, and the steamShortcuts module owns only the mechanism (the option, the merge service, the universal browser/Jellyfin tiles). Emulator modules declare their own Game Mode Tiles (importing a module enables it — repo standard, no enable flags), so a tile existing on a host without its emulator is structurally impossible rather than cross-file discipline.

The rejected alternative was the previous central registry: steam-shortcuts.nix read `config.hostConfig.emulators.<name>.enable or false` for every emulator and silently dropped tiles whose options were undeclared. That kept all tiles in one file but meant adding emulator N+1 touched two files, and a typo'd option path failed silent (tile just missing). The inversion trades that for a coupling rule: a module that declares a tile requires the steamShortcuts module to be imported on that host, and a host that imports an emulator module without importing steamShortcuts fails evaluation loudly ("option does not exist"). Loud-and-explicit was chosen over silent-drop deliberately — do not "fix" the eval error by re-adding `or false` guards; import steamShortcuts on the host instead.
